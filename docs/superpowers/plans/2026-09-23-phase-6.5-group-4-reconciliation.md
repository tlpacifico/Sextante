# Phase 6.5 — Grupo 4 (Acerto de saldo / reconciliação) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O utilizador indica "o saldo real da conta X a DD/MM era Y"; o sistema calcula o saldo a essa data (grupo 2), e se houver diferença cria uma única transação `Kind = Adjustment` (sem categoria, `Inflow` se o real é maior, `Outflow` se menor, descrição "Acerto de saldo") que faz o saldo à data coincidir com o real. Acertos não contam nos totais/orçamentos (já garantido pelo grupo 1 — só `Regular` conta), contam no saldo (já garantido pelo grupo 2), aparecem nas transações como "Acerto" e podem ser apagados (reversão auditável), nunca editados.

**Architecture:** Nova factory de domínio `Transaction.CreateAdjustment`. Novo comando `ReconcileAccountCommand` em `Features/Accounts/` (o acerto é uma operação sobre a conta, não uma transação criada pelo utilizador), com handler em `AccountHandlers` que reutiliza `IAccountBalanceQuery.GetBalanceAsync(accountId, at)` e `ITransactionRepository.AddAsync`. Endpoint `POST /api/financial/accounts/{id}/reconcile`. Sem migration: os CHECKs do grupo 1 (`kind = 0 OR category_id IS NULL`; `(kind = 1) = (transfer_id IS NOT NULL)`) já cobrem `Adjustment` sem categoria e sem `TransferId`. Na UI, um dialog novo `reconcile-account.dialog.ts` aberto a partir do ecrã de contas pré-visualiza a diferença com o `GET /balance?at=` já existente antes de confirmar; o ecrã de transações passa a mostrar acertos como "Acerto" sem botão de editar.

**Tech Stack:** .NET 10, EF Core + Npgsql, Wolverine (`[NonTransactional]`), FluentValidation, PostgreSQL 16, Angular 21 + PrimeNG, xUnit/FluentAssertions/Testcontainers, Karma/Jasmine.

**Spec:** `specs/2026-09-23-phase-6.5-transfers-credit-card/` (`plan.md` §4; `requirements.md` §C, D4, D5, D7, D10; `validation.md` passos 5 e 7; `docs/adr/ADR-014-transfers-and-account-balance.md`).

## Rulings de desenho (decididos ao escrever este plano)

- **R1 — Hora do acerto: `OccurredAt = min(D às 12:00 UTC, agora)`.** *(Revisto na revisão final: era 23:59:59 UTC, que em UTC+1 aparecia no dia seguinte.)* O meio-dia UTC fica dentro do corte do saldo "à data D" (grupo 2, inclusivo até `< D+1 00:00Z`) e é mostrado no próprio dia D em qualquer fuso até ±11h. Se D é hoje antes do meio-dia, fica "agora" (nunca no futuro — `Build` recusa futuro).
- **R2 — `D > hoje (UTC) + 1 dia` → 400 `ReconciliationDateInFutureException`; `D < OpeningBalanceDate` → 400 `ReconciliationBeforeOpeningBalanceException`.** *(Revisto na revisão final: tolera-se um dia porque, em fusos à frente de UTC, o "hoje" local pré-preenchido pelo dialog ainda é "amanhã" em UTC durante a primeira hora do dia; a hora do acerto é limitada a "agora" por R1.)* Um acerto anterior à data do saldo inicial seria ignorado pelo cálculo de saldo (grupo 2) — o acerto não teria efeito, logo recusa-se.
- **R3 — Diferença zero: nenhuma transação criada; 200 com `Adjustment = null`.** Não é erro — é a resposta "está reconciliado".
- **R4 — `ActualBalance` é um `decimal` na moeda da conta, qualquer sinal, qualquer tipo de conta.** D7 restringe só o *saldo inicial* negativo; uma conta à ordem pode estar a descoberto. Na UI, cartões de crédito mostram texto de ajuda: "Dívida é negativa (ex.: −350,00)", coerente com o ecrã de contas que já mostra a dívida como saldo negativo. Revisitável (ex.: campo "Dívida" positivo) sem mudar o contrato.
- **R5 — Pré-visualização via `GET /accounts/{id}/balance?at=D` existente**, não um endpoint de "dry-run". O cálculo da diferença na UI é `actual − calculated`; o servidor recalcula ao confirmar (fonte de verdade), e a resposta traz os três valores.
- **R6 — Acertos apagam-se pelo `DELETE /api/financial/transactions/{id}` existente** (`Archive()` já só recusa `Transfer`, R8 do grupo 3); não se editam (`Update`/`SetCategory` já têm `EnsureRegular()` → `TransactionNotRegularException` → 400). Na UI, a linha de acerto não tem botão de editar e fica fora das ações em lote de recategorizar/converter.
- **R7 — Acerto não é "mais um tipo de transação criado pelo utilizador"**: não há `POST /transactions` com `kind = Adjustment`; o único caminho de criação é a reconciliação.
- **R8 — Contas não encontradas / de outro tenant → handler devolve `null` → 404** (mesmo padrão dos restantes handlers de `AccountHandlers`, sem exceção).

## Review Focus

1. **Saldo à data após acerto = saldo real indicado**, incluindo quando D é hoje (acerto em "agora") e quando D é passado com transações posteriores a D (o saldo *atual* ≠ real, mas o saldo a D = real). Teste de integração com transação posterior a D.
2. **Totais/orçamentos intocados**: o summary do mês e o `BudgetProgress` não mudam após um acerto de saída numa conta com orçamento ativo (validation.md passo 7).
3. **Cartão de crédito com dívida**: saldo calculado −500, real −650 → acerto `Outflow` 150; real −400 → `Inflow` 100 (sinais trocados são o erro mais provável).
4. **Datas-limite**: D = `OpeningBalanceDate` é aceite (inclusivo); D − 1 → 400; D = amanhã → 400.
5. **Multi-tenancy**: reconciliar conta de outro tenant → 404 e nenhuma transação criada em nenhum tenant.

Handler (em `AccountHandlers`, `[NonTransactional]` já está na classe):

```csharp
public static async Task<ReconcileAccountResponse?> Handle(
    ReconcileAccountCommand command,
    IAccountRepository accounts,
    IAccountBalanceQuery balances,
    ITransactionRepository transactions,
    ITenantContext tenant,
    ITenantCurrencyResolver currency,
    IExchangeRateService exchangeRates,
    IIntegrationEventPublisher events,
    CancellationToken cancellationToken)
{
    var account = await accounts.GetByIdAsync(command.AccountId, cancellationToken);
    if (account is null)
    {
        return null; // R8 — outro tenant ou inexistente → 404
    }

    var now = DateTimeOffset.UtcNow;
    var latestAcceptedDate = DateOnly.FromDateTime(now.UtcDateTime).AddDays(1); // R2 — tolerância de fuso
    if (command.Date > latestAcceptedDate)
    {
        throw new ReconciliationDateInFutureException();
    }

    if (command.Date < account.OpeningBalanceDate)
    {
        throw new ReconciliationBeforeOpeningBalanceException();
    }

    var calculated = await balances.GetBalanceAsync(account.Id, command.Date, cancellationToken);
    if (calculated is null)
    {
        return null; // arquivada em concorrência — mesmo tratamento de GetAccountBalanceQuery
    }

    var actual = new Money(command.ActualBalance, account.Currency);
    var difference = command.ActualBalance - calculated.Amount;
    if (difference == 0m)
    {
        return new ReconcileAccountResponse(
            account.Id, command.Date, calculated, actual, new Money(0m, account.Currency), null);
    }

    // R1 — meio-dia UTC do dia D, nunca no futuro.
    var noonOfDate = new DateTimeOffset(command.Date.ToDateTime(new TimeOnly(12, 0), DateTimeKind.Utc));
    var occurredAt = noonOfDate < now ? noonOfDate : now;

    var primaryCurrency = await currency.GetPrimaryCurrencyAsync(cancellationToken);
    var snapshot = await exchangeRates.ResolveAsync(
        account.Currency, primaryCurrency, occurredAt, cancellationToken);

    var adjustment = Transaction.CreateAdjustment(
        account.Id,
        difference > 0m ? TransactionDirection.Inflow : TransactionDirection.Outflow,
        occurredAt,
        new Money(Math.Abs(difference), account.Currency),
        "Acerto de saldo",
        tenant.TenantId,
        snapshot,
        now);

    await transactions.AddAsync(adjustment, cancellationToken);
    await transactions.SaveChangesAsync(cancellationToken);

    await events.PublishAsync(
        new TransactionCreatedIntegrationEvent(
            adjustment.Id,
            tenant.TenantId.Value,
            adjustment.AccountId,
            null,
            adjustment.Amount.Amount,
            adjustment.Amount.Currency,
            adjustment.OccurredAt,
            DateTimeOffset.UtcNow),
        cancellationToken);

    return new ReconcileAccountResponse(
        account.Id, command.Date, calculated, actual,
        new Money(difference, account.Currency),
        TransactionHandlers.ToResponse(adjustment));
}
```
